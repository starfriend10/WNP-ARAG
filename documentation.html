About WNP-ARAG

AI-enabled exploration of wastewater nutrient regulations

WNP-ARAG combines regulatory data, semantic retrieval, agentic evidence assessment, and grounded answer generation to support efficient policy exploration

D

Regulatory data

The platform draws from an indexed collection of wastewater nutrient regulations, planning documents, BMAPs, TMDLs, water-quality rules, implementation materials, and related guidance

The current collection is designed to support exploration of nitrogen and phosphorus management, wastewater planning, policy interpretation, and regulatory implementation requirements

R

Semantic retrieval

The system searches the indexed document collection using semantic similarity rather than relying only on exact keyword matches

Retrieved passages are ranked and accumulated so that the answer can be linked to visible supporting evidence

A

Agentic RAG

WNP-ARAG evaluates whether the retrieved context is sufficient and may refine the search when additional information is needed

The search process is bounded by safeguards such as maximum search rounds, repeated-query detection, and checks for new supporting passages

U

Updatable policy knowledge

The indexed policy collection can be expanded as new regulations, amendments, planning documents, and implementation guidance become available

This allows the platform to evolve with changing policy needs while preserving evidence-grounded retrieval and transparent source review

Understanding the outputs

How to read the Regulation Explorer results

A completed request may include four complementary outputs

A

Grounded answer

The answer summarizes the retrieved evidence in direct language and may note when applicability depends on jurisdiction, facility type, effective date, or other regulatory conditions

Review this section first, then examine the supporting sources for verification
S

Supporting sources

Source cards show the regulatory documents and matched passages used to support the answer, including page information and retrieval metadata when available

Important conclusions should be checked against the complete original document
J

Search Journey

The Search Journey shows how the agent formulated searches, retrieved evidence, assessed completeness, refined the query, or stopped because a safeguard was reached

The selected number of search rounds is a maximum rather than a guaranteed total
T

Technical Details

Technical Details provide diagnostic information about request timing, retrieval rounds, evidence status, model readiness, vector-database readiness, and GPU use

This section is mainly intended for developers, reviewers, and troubleshooting
R

Readiness indicators

The Explorer shows separate status indicators for the GPU, language model, state vector database, and uploaded-document vector database. These states are checked again before each question so the interface does not rely on stale readiness information after a long processing job or server restart

Uploaded-document sessions are also validated before a document-based question
L

Live search progress

The main progress panel and Search Journey use the same streamed backend updates. Users can follow the transition from search preparation to passage retrieval, evidence assessment, query refinement, and final response generation

The live panel is hidden after completion because the final Search Journey remains available

Server connection

How the public interface connects to the AI backend

WNP-ARAG separates the public website from the computational backend

GitHub Pages Hosts the public website, documentation, interface layout, and sample questions
→
Gradio API Transfers user questions and returned results between the browser and backend
→
Hugging Face Space Runs retrieval, evidence assessment, the vector database, and language-model inference

When a user submits a question, the GitHub Pages frontend sends the request through the Gradio API to the WNP-ARAG Space on Hugging Face. The backend retrieves relevant regulatory passages, evaluates whether the evidence is sufficient, may refine the search, and returns the grounded answer together with sources and diagnostics.

Hugging Face Spaces may enter a sleeping or non-running state after inactivity. The frontend therefore checks server availability, keeps the Ask button disabled until the backend becomes reachable, and shows elapsed startup time while the Space is waking. If Hugging Face reports a terminal hardware scheduling failure, the startup timer stops because no GPU is currently available for the requested Space.

The most common error due to GPU unavailability

Model ready

The server, vector database, and language model are available for requests

Starting

Connecting to the WNP-ARAG server. Startup may require several minutes

Building

The Hugging Face Space is building the backend. This may take several minutes

Paused

The backend is unavailable. The developers may be testing or troubleshooting the system, and the Space must be restarted by its owner

Build error

The backend failed to start due to a build error. Please contact the platform owner

Over 10 min

The backend is taking longer than expected, likely because of Hugging Face infrastructure or GPU scheduling. Please come back and try again later

Scope and limitations

What the platform currently covers

Current scope

Wastewater nutrient regulations
BMAPs and TMDLs
Wastewater planning and regulatory implementation requirements
Nitrogen and phosphorus management
Water-quality rules and related regulatory guidance

Current limitations

Coverage depends on the indexed document collection
Recent updates or jurisdiction-specific materials may not yet be included
Retrieved passages may omit applicable exceptions or implementation details
Important conclusions should be verified against the original documents
WNP-ARAG supports regulatory exploration rather than replacing legal judgment

Uploaded-document workflow

Formats: PDF, HTML, HTM, TXT, DOC, DOCX, PPTX
TXT, PDF, and HTML process fastest; DOC and DOCX may take longer
Maximum file size: 25 MB
Maximum length: 300 normalized-PDF pages
Download includes the vector database and normalized PDF

Temporary-session behavior

Uploaded documents stay separate from the public state databases
Sessions expire after 30 minutes of inactivity
Space sleep or restart can remove the temporary database
Session validity is checked before each document question
Lost sessions require rebuilding the vector database
